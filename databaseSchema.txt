users (keyed by a uid): (no reason to store email here because it's already in the firebase auth)
- username (string)
- artifacts they've saved (object mapping lotNumber -> true)
- admin (boolean)

artifacts (keyed by a lotNumber):
- name (string)
- description (string)
- category (enum with 16 options, stored as an integer)
- material (enum with 11 options, stored as an integer)
- dynastyPeriod (enum with 18 options, stored as an integer)
- culturalOrigin (string)
- currentLocation (string)
- acquisitionMethod (string)
- provenance (string)
- accessionNumber (number)
- notes (string)
- imageUrl (string, will be stored in Supabase)
- likes (dictionary that maps uid -> true for the likes, to unlike you just remove your userId and we count the # of children to determine the # of likes)
- searchKeywords (string, automatically generated by the app upon editing/creating an artifact, and is used for search)

artifactComments (keyed by a lotNumber):
- inside an object, we have another object mapping uid -> another object that holds their comments
    - in this object, we map comment id -> their comment data, the comment data has:
        - content (string)
        - timestamp (number, unix timestamp)
        - username (string, necessary to save queries, we will have to go through all artifacts to change all of the stored username's upon changing their username, but since that operation shouldn't happen very often, it's definitely worth it)

PERMISSIONS:
if a user is not logged in, then they see nothing.
if a user is logged in (and they're not an admin):
- they can see every user's username (but nothing else)
- they can see their own data, and then can also edit their own data to be anything (except they can never modify the 'admin' field to be anything except 'false' to prevent privilege escalation)
- they can see all the artifact data, but they can't modify any of it
- they can see all of the artifactComments data, and they can only edit the object associated to their uid

if a user is logged in (and they're an admin):
- they have the same control over 'users' as above
- they have complete access to 'artifacts', EXCEPT they have no control over 'likes' unless it's their own (BUT, they are able to delete the entire artifact, including 'likes'. hopefully firebase can implement that kind of a rule)
- they have the ability to delete comments of users in 'artifactComments' (but not modify or create unless its their own comment)
